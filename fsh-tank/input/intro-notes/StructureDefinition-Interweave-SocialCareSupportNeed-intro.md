**Definition:** The social care needs an adult/carer has as defined within The Care and Support (Eligibility Criteria) Regulations 2015 and identified as part of the Care Eligibility Assessment.

## **Introduction**
This profile sets minimum expectations for the Social Care Support Need resource which is modelled using the FHIR Condition resource. The FHIR Condition resource was chosen to model the  as it was the most akin in terms of logic and structure. Many of the irrelevant health fields have been stripped from this resource which has created a clear and concise model for population. We will simply refer to this resource as a Support Need throughout the remainder of the notes section. 

### **Coverage and references**
  - A Data Provider MUST offer FHIR resources to represent its own service users' support needs. 
 
    * Needs that are being recorded and supported by other orgs – 
  	If the needs are not recorded within the system, then the organization would not be able to share it, that is not something specific to this particular resource, but would be universal to all resources. 
    *	If those needs are recorded in the system then it should be shared (may be with a comment to say this is manged by external org – this is just one possible solution and may not be achievable, however depending on the use case we can discuss the specific scenarios with the data provider and come up with some options). 

### **Support Need Period**
The Support Need Period is the duration of the identified need. The Condition resource offered two date fields which seemed to be suitable candidates for holding this data these being 'onset' and 'abatement'. However, the description of these fields, and rules which needed to be applied during their usage in order to be FHIR compliant, made using them unnecessarily complicated. Therefore, we have chosen to remove both date fields, and create our own extension, SupportNeedPeriod, to house this data. 

### **Mandatory fields**
The following fields are mandatory:

- **clinicalStatus** – A mandatory flag to indicate whether the support need is active or not. We limit the valueset to the following values; active | inactive

- **category** – This provides a level of categorisation i.e. if the need relates to an adult or a carer. We extend the care connect valueset to include a defined a list of codes derived based on The Care and Support (Eligibility Criteria) Regulations 2015. 

- **code** – code is used to house the 'type' of support need. This should always be known, and vital for meaningful display purposes. We have defined a list of specified outcomes in The Care and Support (Eligibility Criteria) Regulations 2015 with Light touch to Adult Social Care Record (MODS) standard to define codes.

- **subject.patient** – The person which is the subject of the support need.

- **assertedDate** – The date that the support need was identified as part of an assessment.

### **Optional fields**
Other fields are optional and may be populated if known – on the understanding that not all data consumers will necessarily make use of them. Optional fields to note include:

- **partOfAssessment** – An extension has been created which will allow an optional link to the assessment in which this particular need was identified. 

- **identifier:localIdentifier** – As with most other resources, there is the option to include a local identifier which may help to identify the record at a local level.

- **note** – use note to enter further detail on the support need.

- **asserter** – The source of the information about the identified need. This can be a reference to a practitioner.

- **supportNeedPeriod** – Should be populated with the start and end date of the need as identified as part of an assessment

### **Discouraged or Removed fields**

- **context** – This field is deprecated in R4 and has been removed from our specification.
- **abatement** and **onSet** – Removed to avoid confusion when supplying the Support Reason Period (See mandatory notes section above). 
- **code(SNOMEDCT)** – This slice created by Care Connect has been removed to avoid confusion with the list of support need types generated by the Social Care Data Standards working group.
- **ConditionEpisode-1** A Care connect extension which is not relevant here.

The following fields have been removed as they capture Health Care related data which is not relevant in Social Care:
    
  - **severity** 
  - **bodySite** 
  - **stage** 
  - **evidence**
